# JHCIS Queue — ระบบพิมพ์ใบนำทาง A5

Next.js App Router + TypeScript + MySQL2 สำหรับใช้งานภายในเครื่อง/หน่วยบริการ

## เริ่มใช้งาน

ติดตั้ง Node.js 20.9 ขึ้นไป แล้วรันในโฟลเดอร์นี้:

```powershell
npm install
npm run dev
```

เปิด http://127.0.0.1:3000 สำหรับ production ใช้ `npm run build` แล้ว `npm start`

## ค้นหาและพิมพ์

การติดตั้งใหม่เริ่มต้นเป็นโหมดตัวอย่าง ใช้ HN `00001` (ข้อมูลสมมติ) ค้นหา ตรวจสอบข้อมูล แล้วกดพิมพ์ เลือก A5 แนวตั้ง สเกล 100% ปิด headers/footers ในหน้าต่างพิมพ์ ฟอร์มอิงภาพอ้างอิงและขยายเป็น A5 หากข้อมูลยาวมากควรตรวจจำนวนหน้าก่อนพิมพ์

## ตั้งค่าฐานข้อมูล

1. กดตั้งค่า ใส่รหัส `12345678` เซสชันอายุ 30 นาที ปิดหน้าตั้งค่าจะออกจากเซสชัน
2. ระบุ Host, Port, Database, Username และ Password แล้วทดสอบการเชื่อมต่อ
3. ปรับ SQL ให้ตรงกับ schema ของหน่วยบริการ ใช้ SELECT หนึ่งคำสั่ง ใช้ `?` แทน HN หนึ่งตำแหน่ง ไม่ใส่ semicolon SQL เริ่มต้นอ่าน `person` ของ JHCIS โดยใช้ `pid` เป็น HN และ JOIN ตารางคำนำหน้า สิทธิ และชื่อพื้นที่
4. ส่งคืนชื่อคอลัมน์ `hn, name, cid, sex, birthDate, rightName, address, allergy, room, authCode` โดยใช้ AS ตั้ง alias; ต้องมี hn และ name วันเกิดรูปแบบ YYYY-MM-DD เพศต้องแปลงเป็นข้อความที่ต้องการแสดง
5. HN ใช้ `person.pid` รับตัวเลข 1–8 หลัก และเติมศูนย์ด้านหน้าเฉพาะ HN ที่สั้นกว่า 5 หลัก โดย HN 6–8 หลักจะแสดงครบตามเดิม หาก pid ซ้ำหลาย pcucodeperson ระบบจะแจ้งให้เพิ่มเงื่อนไขหน่วยบริการใน SQL (คง LIMIT 2 เพื่อจับข้อมูลซ้ำ) ไม่แก้ไขข้อมูลผู้ป่วย
6. ปิดโหมดตัวอย่างและบันทึก ข้อมูลจริงจะถูกอ่านหลังจากนั้น

การทดสอบการเชื่อมต่อตรวจเฉพาะการเชื่อมต่อด้วย SELECT 1; การตรวจ schema ทำเมื่อค้นหา HN จริง ค่า MySQL เก็บฝั่งเซิร์ฟเวอร์ใน `data/settings.json` (ไม่ถูก commit) รหัสผ่านฐานข้อมูลไม่ถูกส่งกลับเบราว์เซอร์ เว้นช่องรหัสผ่านว่างเพื่อใช้ค่าเดิม ข้อมูลผู้ป่วยไม่เก็บใน localStorage และ API ส่ง Cache-Control: no-store

ใช้บัญชี MySQL สิทธิ SELECT เท่านั้น จำกัดสิทธิอ่านไฟล์ `data` ให้บัญชีที่รันแอป ไฟล์ตั้งค่ามีรหัสผ่านฐานข้อมูล สคริปต์เริ่มต้น bind เฉพาะ 127.0.0.1; ก่อนเปิดใช้ผ่านเครือข่ายต้องเพิ่มระบบยืนยันตัวตนเจ้าหน้าที่ HTTPS และมาตรการควบคุมการเข้าถึงตามหน่วยบริการ รหัสหน้าตั้งค่าไม่ใช่ระบบล็อกอินค้นหาผู้ป่วย สามารถเปลี่ยนรหัสตั้งค่าด้วย environment variable `SETTINGS_PASSWORD` แล้ว restart เซสชัน/จำกัดการลองรหัสอยู่ในหน่วยความจำ จึงเหมาะกับการรันหนึ่ง instance

## เลขคิวและข้อมูล JHCIS

แสดงเลข `Q 1`, `Q 2`, … ที่ด้านขวาแทน QN เดิม ไม่มี A50 ก่อนกดพิมพ์แสดง `Q —` เมื่อกดปุ่มพิมพ์จะออกเลขใหม่และบันทึกใน `data/queue.json` เริ่มที่ `Q 1` ใหม่ทุกวันตามเวลาไทย (Asia/Bangkok) โดยตรวจวันที่เมื่อออกคิวครั้งแรกหลังเที่ยงคืน ไม่ต้องเปิดโปรแกรมค้างไว้ การเปิดโปรแกรมใหม่ในวันเดียวกันจะนับต่อจากเดิม เมื่ออัปเกรดไฟล์คิวรุ่นเดิมที่ยังไม่มีวันที่ จะเก็บเลขปัจจุบันไว้เป็นคิวของวันนี้ และเริ่มรีเซ็ตในวันถัดไป การพิมพ์ซ้ำผ่านปุ่มจะออกเลขใหม่ การยกเลิกหน้าต่างพิมพ์ยังถือว่าใช้เลขแล้ว เพราะเบราว์เซอร์ไม่ยืนยันผลเครื่องพิมพ์ ใช้ปุ่มพิมพ์ของระบบเพื่อออกเลข (Ctrl+P ไม่ออกเลขใหม่) ไม่ควรลบไฟล์คิว

ใช้ filesystem lock และ request ID ป้องกันเลขซ้ำและคำขอซ้ำ เหมาะกับเซิร์ฟเวอร์ที่แชร์โฟลเดอร์ data เดียวกัน หากโปรเซสหยุดระหว่างออกเลขอาจทิ้ง data/queue.lock ให้หยุดเซิร์ฟเวอร์ทุก instance และตรวจ queue.json ก่อนลบ lock ที่ค้าง ไม่รีเซ็ต counter

ข้อมูลจับคู่จาก pid, fname/lname/prename, idcard, sex, birth, rightcode, allergic และที่อยู่ทะเบียนจากคอลัมน์ *moi พร้อมชื่อพื้นที่จากตารางรหัส ห้องและ Authen Code ไม่ได้อยู่ใน person จึงไม่สมมติข้อมูลการรับบริการ หากต้องการต้องเพิ่ม JOIN แหล่งข้อมูลที่ถูกต้อง

ผู้ดูแลสามารถกด **รีเซ็ตเลขคิว** ในหน้าตั้งค่าการเชื่อมต่อหลังเข้าสู่ระบบ และยืนยันเพื่อให้คิวถัดไปเริ่มที่ Q 1 การรีเซ็ตระหว่างวันอาจทำให้เลขซ้ำกับใบนำทางที่ออกไปแล้ว ไม่เปลี่ยนค่าการเชื่อมต่อ MySQL

เลือกแบบฟอร์มได้ที่หน้าตั้งค่าการเชื่อมต่อ → แบบฟอร์มที่จะพิมพ์ → บันทึกการตั้งค่า มีแบบปัจจุบันพร้อมจุดรับบริการ และแบบเส้นบันทึกที่ไม่มีจุดรับบริการ ทั้งสองแบบใช้กระดาษ A5 ระบบจำตัวเลือกไว้ใน data/settings.json การติดตั้งเดิมที่ยังไม่มีตัวเลือกนี้จะใช้แบบปัจจุบัน
