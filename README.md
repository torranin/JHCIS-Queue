# JHCIS Queue — ระบบพิมพ์ใบนำทางผู้ป่วย A5

ระบบค้นหาข้อมูลผู้ป่วยจากฐานข้อมูล JHCIS และพิมพ์ใบนำทางขนาด A5 พัฒนาด้วย **Next.js App Router, TypeScript และ MySQL2** สำหรับใช้งานภายในเครื่องหรือหน่วยบริการ

## ความสามารถ

- ค้นหาผู้ป่วยด้วย HN จากฟิลด์ `person.pid` หรือเลขบัตรประชาชนจาก `person.idcard`
- แสดงข้อมูลผู้ป่วยและตัวอย่างใบนำทางก่อนพิมพ์
- ออกเลขคิวอัตโนมัติ และเริ่มนับใหม่ทุกวันตามเวลาไทย
- เลือกใบนำทางได้ 4 แบบ
- ตั้งค่าการเชื่อมต่อ MySQL และ SQL ผ่านหน้าเว็บ
- มีโหมดข้อมูลตัวอย่างสำหรับทดลองใช้งาน
- รองรับการเปิดระบบผ่านไฟล์ `.cmd` บน Windows

## เริ่มใช้งาน

ติดตั้ง **Node.js 20.9 ขึ้นไป** จากนั้นเปิด Terminal ในโฟลเดอร์โปรเจกต์

### สำหรับพัฒนา

```powershell
npm install
npm run dev
```

### สำหรับใช้งานจริง

```powershell
npm install
npm run build
npm start
```

เปิดระบบที่ [http://127.0.0.1:3000](http://127.0.0.1:3000)

### เปิดผ่านไฟล์ CMD

ดับเบิลคลิกไฟล์ `Run JHCIS Queue.cmd` แล้วรอระบบเริ่มทำงาน สามารถสร้าง Shortcut ของไฟล์นี้ไว้บน Desktop เพื่อเปิดใช้งานได้สะดวก

เมื่อนำไปใช้เครื่องอื่น ให้คัดลอกโฟลเดอร์โปรเจกต์ ติดตั้ง Node.js และสร้าง Shortcut ใหม่ให้ชี้ไปยังไฟล์ `.cmd` ในเครื่องนั้น การคัดลอกเฉพาะ Shortcut ไม่ได้คัดลอกตัวระบบไปด้วย

> เมื่อแก้ไขซอร์สโค้ด ให้หยุดระบบและรัน `npm run build` ใหม่ก่อนเปิดใช้งานจริง

## ค้นหาและพิมพ์

1. กรอก HN หรือเลขบัตรประชาชน แล้วกด **ค้นหาผู้ป่วย**
2. ตรวจสอบข้อมูลและตัวอย่างใบนำทาง
3. กด **พิมพ์ใบนำทาง**
4. ตั้งค่าการพิมพ์เป็น **A5 แนวตั้ง สเกล 100%** และปิด Headers/Footers

การติดตั้งใหม่เริ่มต้นเป็นโหมดข้อมูลตัวอย่าง สามารถทดลองค้นหาด้วย HN `00001` ซึ่งเป็นข้อมูลสมมติ หากข้อมูลยาว ควรตรวจสอบจำนวนหน้าก่อนสั่งพิมพ์

HN รองรับตัวเลข 1–8 หลัก โดยเติมศูนย์ด้านหน้าเมื่อมีความยาวน้อยกว่า 5 หลัก ส่วนเลขบัตรประชาชนใช้ตัวเลข 13 หลัก

## แบบฟอร์มใบนำทาง

เลือกแบบฟอร์มได้ที่ **ตั้งค่าการเชื่อมต่อ MySQL → แบบฟอร์มที่จะพิมพ์ → บันทึกการตั้งค่า**

| แบบฟอร์ม | รายละเอียด |
|---|---|
| แบบ รพ.สต.Cup - มีจุดรับบริการ | มีรายการจุดรับบริการ ระยะขอบครึ่งนิ้ว และช่อง CC 5 บรรทัด |
| แบบ PCU - มีจุดรับบริการ | รายการจุดรับบริการสำหรับ PCU และช่อง CC 5 บรรทัด |
| แบบ PCU มีจุดรับบริการ v.1 | รูปแบบเดียวกับ PCU โดยจัดเลขคิวไว้ด้านขวา |
| แบบเส้นบันทึก — ไม่มีจุดรับบริการ | เน้นพื้นที่สำหรับเขียนบันทึก ไม่มีรายการจุดรับบริการ |

ทุกแบบใช้กระดาษ **A5** และระบบบันทึกแบบฟอร์มที่เลือกไว้ใน `data/settings.json`

## ตั้งค่าฐานข้อมูล MySQL

1. กด **ตั้งค่าการเชื่อมต่อ** และใส่รหัสเริ่มต้น `12345678`
2. ระบุ Host, Port, Database, Username และ Password
3. กด **ทดสอบการเชื่อมต่อ**
4. ตรวจสอบ SQL ให้ตรงกับโครงสร้างฐานข้อมูลของหน่วยบริการ
5. ปิด **ใช้ข้อมูลตัวอย่าง** แล้วกด **บันทึกการตั้งค่า**

เซสชันหน้าตั้งค่ามีอายุ 30 นาที และสิ้นสุดเมื่อปิดหน้าตั้งค่า สามารถเปลี่ยนรหัสผ่านผู้ดูแลด้วย environment variable `SETTINGS_PASSWORD` แล้วเริ่มระบบใหม่

### SQL และข้อมูลผู้ป่วย

SQL สำหรับค้นหา HN ต้องเป็น `SELECT` หนึ่งคำสั่ง ใช้ `?` แทน HN หนึ่งตำแหน่ง และไม่ใส่ semicolon

SQL เริ่มต้นอ่านข้อมูลจากตาราง `person` ของ JHCIS โดยใช้ `pid` เป็น HN พร้อมเชื่อมตารางคำนำหน้า สิทธิการรักษา และชื่อพื้นที่

ชื่อคอลัมน์ผลลัพธ์ที่ระบบรองรับ:

```text
hn, name, cid, sex, birthDate, rightName, address, allergy, room, authCode
```

- ใช้ `AS` กำหนดชื่อคอลัมน์ให้ตรงกับรายการข้างต้น
- ต้องมี `hn` และ `name`
- วันเกิดใช้รูปแบบ `YYYY-MM-DD`
- เพศควรแปลงเป็นข้อความที่ต้องการแสดง
- หาก `pid` ซ้ำหลาย `pcucodeperson` ให้เพิ่มเงื่อนไขหน่วยบริการใน SQL และคง `LIMIT 2` เพื่อให้ตรวจพบข้อมูลซ้ำ

ข้อมูลหลักมาจาก `pid`, `fname`, `lname`, `prename`, `idcard`, `sex`, `birth`, `rightcode`, `allergic` และข้อมูลที่อยู่ทะเบียนกลุ่มคอลัมน์ `*moi`

ห้องรับบริการและ Authen Code ไม่ได้อยู่ในตาราง `person` หากต้องการใช้ข้อมูลเหล่านี้ ต้องเชื่อมกับแหล่งข้อมูลการรับบริการที่ถูกต้อง

> การทดสอบการเชื่อมต่อใช้ `SELECT 1` เพื่อตรวจการเชื่อมต่อเท่านั้น การตรวจสอบ SQL และโครงสร้างตารางจะเกิดขึ้นเมื่อค้นหาข้อมูลจริง

## การทำงานของเลขคิว

- แสดงเลข `Q 1`, `Q 2`, … โดยไม่มีรหัส A50
- ก่อนกดพิมพ์จะแสดง `Q —`
- ออกเลขใหม่เมื่อกดปุ่มพิมพ์ และบันทึกไว้ใน `data/queue.json`
- เริ่มที่ `Q 1` ใหม่ทุกวันตามเขตเวลา `Asia/Bangkok` โดยตรวจวันที่เมื่อออกคิวครั้งแรกของวัน
- ปิดและเปิดระบบใหม่ในวันเดียวกันจะนับต่อจากเลขเดิม
- การพิมพ์ซ้ำผ่านปุ่มจะออกเลขใหม่
- การยกเลิกหน้าต่างพิมพ์ยังถือว่าใช้เลขคิวนั้นแล้ว
- การกด `Ctrl+P` ไม่ออกเลขคิวใหม่

ผู้ดูแลสามารถรีเซ็ตเลขคิวผ่านหน้าตั้งค่า โดยต้องยืนยันก่อนให้คิวถัดไปเริ่มที่ `Q 1` การรีเซ็ตระหว่างวันอาจทำให้เลขซ้ำกับใบนำทางที่ออกไปแล้ว

ระบบใช้ filesystem lock และ request ID เพื่อป้องกันการออกเลขซ้ำจากคำขอพร้อมกันหรือคำขอซ้ำ หากโปรเซสหยุดผิดปกติจนมี `data/queue.lock` ค้าง ให้หยุดทุก instance และตรวจสอบ `queue.json` ก่อนลบเฉพาะ lock ที่ค้าง ไม่ควรลบไฟล์คิวเพื่อแก้ปัญหา

## การเก็บข้อมูลและความปลอดภัย

- เก็บค่าการเชื่อมต่อฝั่งเซิร์ฟเวอร์ใน `data/settings.json` ซึ่งไม่ถูก commit
- ไม่ส่งรหัสผ่านฐานข้อมูลกลับไปยังเบราว์เซอร์ เว้นช่อง Password ว่างเพื่อใช้ค่าเดิม
- ไม่เก็บข้อมูลผู้ป่วยใน `localStorage`
- API ข้อมูลผู้ป่วยใช้ `Cache-Control: no-store`
- ควรใช้บัญชี MySQL ที่มีสิทธิ์ `SELECT` เท่านั้น
- จำกัดสิทธิ์เข้าถึงโฟลเดอร์ `data` เพราะไฟล์ตั้งค่ามีรหัสผ่านฐานข้อมูล

สคริปต์เริ่มระบบผูกกับ `127.0.0.1` สำหรับใช้งานในเครื่อง หากต้องการเปิดผ่านเครือข่าย ควรเพิ่มระบบยืนยันตัวตนเจ้าหน้าที่ HTTPS และการควบคุมสิทธิ์เข้าถึงก่อนใช้งาน

รหัสผ่านหน้าตั้งค่าป้องกันเฉพาะการตั้งค่าระบบ ไม่ใช่ระบบล็อกอินสำหรับค้นหาผู้ป่วย เซสชันและการจำกัดการลองรหัสเก็บในหน่วยความจำ จึงเหมาะกับการรันแอปหนึ่ง instance
